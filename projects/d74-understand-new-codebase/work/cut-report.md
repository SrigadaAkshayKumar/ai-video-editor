## Clean script (what the viewer will hear)

Your manager just gave you access to a project with two thousand files and said, "Go through the code and get comfortable." No guide, no video. Just a folder, if that is going to be you, this video is for you. In the next five minutes, I will give you three steps to understand a new code base in your first week and the one habit that makes seniors trust you. Stay till the end, because the third step is the one almost every fresher skips. First, why this feels so hard? In college, you wrote code from an empty file. You knew every line because you wrote every line. At work, you read code that many people wrote over many years. It has old fixes, strange names, and parts nobody remembers. So, your brain says, "I understand nothing." Here is the truth, guys. Nobody understands a whole code base in a week. Not you, not the senior next to you. The goal for week one is not to understand everything. The goal is to understand one path from start to finish. Step one, run it before you read it. Ask your buddy or lead for the setup guide and get the project running on your laptop. Many freshers read code for two days and only then try to run it. That is backwards. When the app runs, you can click a button and see what happens. You can see the screen, the output, the logs. Now the code has a face. You are no longer reading text. You are following something alive. If the setup fails, do not sit silently for hours. Write down the exact error, what you already tried, and then ask. We covered the 30-minute rule in an earlier video. Use it here. Step two, trace one small feature from the click to the data. Pick something tiny, a login button, a search box, a single report. Find where the user clicks, then find the function that runs next, then the next one. Keep going until you reach the database or the outside service. Use the search tool in your editor. Search for the words you see on the screen. The text on a button usually leads you straight to the code behind it. Use the debugger and put a breakpoint so you can watch the path step by step. Draw it on paper, four or five boxes with arrows. That small drawing is worth more than two days of scrolling. Now, the third step, the one most fresher skip, write down what you learned and share it. Keep a simple notes file, what the project does, how to run it, the path you traced and your questions, every question, even the small ones. Then, after a few days, go to your lead with this. Say, I traced the login flow. Here is my drawing. Can you check if I have understood it correctly? See what just happened. You did not say, I don't understand. You showed your effort and you made it easy to correct you. Seniors love this and here is a bonus. Many teams have an outdated setup guide. If you fix it with your notes, your first contribution is already done and nobody can say you did nothing in week one. Before we finish, three traps to avoid. One, do not change code. You do not understand just to see what happens. Always work on your own branch. Two, do not copy a solution from an AI tool and paste it in without understanding it. If a senior asks why, you must be able to explain it. Three, do not compare yourself with the person who has been on the project for three years. They have a three year head start. You have a notes file and a fresh pair of eyes and that is a real strength. So to sum up, run it first. Trace one feature, write it down and share it. That is how you turn a scary folder into a project you can work on. Now tell me guys, is there a code base or a tool that scares you right now? Comment the word code and tell me where you get stuck.
